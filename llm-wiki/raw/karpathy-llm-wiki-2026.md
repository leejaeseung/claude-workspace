## 핵심 문제 제기

현재 대부분의 사용자는 AI를 "똑똑한 검색창"처럼 사용한다:
- 질문 → 답변 받음 → 종료
- 비슷한 질문이 나오면 처음부터 반복
- 대화 기록은 흩어지고 지식이 축적되지 않음

## LLM Wiki의 3층 구조

### 1. Raw Sources (원본 자료층)
- 기사, 논문, 이미지, 데이터 파일 저장
- **핵심 원칙: 불변성** — AI는 읽기만 수행
- 진실의 기준점 역할

### 2. The Wiki (위키층)
- AI가 직접 작성하는 마크다운 파일
- 요약, 개념, 인물, 비교, 종합 문서 포함
- 새 자료 입력 시 기존 위키 자동 갱신
- "한 개의 새 소스가 10~15개 페이지를 건드릴 수 있음"

### 3. The Schema (규칙파일층)
- CLAUDE.md 또는 AGENTS.md
- 위키 구조 정의
- 처리 순서 및 우선순위 설정
- LLM을 "챗봇"에서 "위키 관리자"로 전환

## 지식 컴파일러 방식

원본 읽기 → 핵심 추출 → 기존 문서 연결 → 충돌 반영 → 인덱스 갱신 → 구조 정리

## 추가 구조 요소

- **index.md**: 위키 전체 탐색용 카탈로그
- **log.md**: 자료 입력, 질의 및 정리 기록
- "임베딩 기반 RAG 없이도 moderate scale에서 잘 작동"

## 시작 가이드

### 1단계: 주제 선정
한국어 교육 문법, 산업 리서치, 투자 공부, 제품 아이디어, 논문 읽기 노트 등

### 2단계: raw/ 폴더 생성
웹 기사, PDF, 이미지, 노트 저장. 정교한 분류보다 원본 보존 우선.

### 3단계: 규칙 파일 작성 (CLAUDE.md)
```
- 새 자료 입력 시 요약 페이지 작성
- 관련 개념 페이지 링크
- index.md 갱신
- 가치 있는 질문 결과는 새 페이지 저장
- 충돌하는 주장 표시
```

### 4단계: 소규모 시작
처음부터 100개 자료 금지. 3~5개로 시작해 AI 동작 방식 관찰.

## 적용에 강한 분야

- 장기 리서치
- 시험 공부
- 독서 노트
- 업무 문서 축적
- 회의 기록 및 프로젝트 히스토리
- 여행 조사
- 취미 분야 탐구

## 핵심 메시지

> "AI를 매번 새로 불러 쓰는 도구로만 두지 말고, 자료와 질문이 시간이 갈수록 강해지는 구조로 변환"
