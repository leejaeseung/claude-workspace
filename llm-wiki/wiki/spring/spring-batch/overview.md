## 정의

> "대용량 레코드 처리에 필수적인 기능을 제공하는 경량의 종합적인 배치 프레임워크"

Spring Batch는 일괄 처리(Batch Processing)를 위한 Java 프레임워크다.
정기적으로 대량 데이터를 처리해야 하는 엔터프라이즈 시스템의 요구를 충족하기 위해 설계됐다.

---

## 배치 처리가 필요한 상황

| 시나리오 | 예시 |
|---------|------|
| 대용량 데이터 처리 | 수백만 건 DB 레코드 변환 |
| 정기 작업 자동화 | 매일 밤 정산 처리, 월말 리포트 |
| 데이터 마이그레이션 | 시스템 전환 시 데이터 이관 |
| 반복적 ETL | 외부 데이터 수집 및 적재 |
| 오프라인 처리 | 사용자 요청 없이 백그라운드 실행 |

---

## 핵심 특징

| 특징 | 설명 |
|------|------|
| **트랜잭션 관리** | 청크 단위 트랜잭션으로 안정성 보장 |
| **청크 기반 처리** | 커밋 인터벌 단위로 대량 데이터 효율 처리 |
| **선언적 I/O** | 다양한 ItemReader/Writer 기본 제공 |
| **시작/중지/재시작** | Job 실행 제어 및 중단 지점 재개 |
| **Skip / Retry** | 오류 복원력 (건너뛰기 / 재시도) |
| **모니터링** | Micrometer 메트릭, 실행 상태 추적 |
| **확장성** | 멀티스레드, 파티셔닝, 원격 청킹 |

## 기존 스케줄러와의 차이

| 구분 | 일반 스케줄러 (@Scheduled) | Spring Batch |
|------|--------------------------|-------------|
| 실행 상태 추적 | ❌ | ✅ (JobRepository) |
| 재시작/재개 | ❌ | ✅ (ExecutionContext) |
| Skip/Retry | ❌ | ✅ |
| 대용량 최적화 | ❌ | ✅ (Chunk, Paging) |
| 메타데이터 저장 | ❌ | ✅ (BATCH_* 테이블) |

## 언제 Spring Batch를 써야 하나

**써야 할 때**
- 수만 건 이상 데이터를 처리하는 배치 작업
- 작업 실패 시 재시작/재개가 필요할 때
- 처리 결과를 추적하고 감사해야 할 때
- 복잡한 오류 처리(Skip/Retry)가 필요할 때

**굳이 안 써도 될 때**
- 단순한 주기적 메서드 호출 (`@Scheduled`로 충분)
- 소량 데이터 처리
- 상태 추적이 불필요한 일회성 스크립트
