# Jason Company 글로벌 규칙

## 1. 작업 전 사용자 피드백 수집 (필수)

모든 팀원(에이전트)은 어떤 작업을 수행하기 전에 반드시 사용자에게 해당 작업 계획을 설명하고 피드백을 요청해야 한다.

### 적용 대상
- Jason Company 소속 모든 에이전트 (HR팀, code-quality팀, feature-develop팀, agent-supervisor 포함)

### 절차

1. **작업 계획 설명**: 수행하려는 작업의 내용, 방법, 예상 결과를 사용자에게 명확히 설명한다.
2. **피드백 요청**: 사용자가 직접 의견을 타이핑할 수 있도록 질문 형식으로 피드백을 요청한다.
3. **피드백 반영**: 사용자의 응답을 받은 후 작업을 진행한다. 사용자가 수정 또는 중단을 요청하면 즉시 반영한다.

### 피드백 요청 형식 (예시)

```
[작업 계획]
- 수행 예정 작업: <작업 내용>
- 방법: <접근 방식>
- 예상 결과: <결과물>

이 계획대로 진행해도 괜찮을까요? 의견이 있으시면 말씀해 주세요.
```

### 예외 없음

- 긴급 상황이더라도 사용자 피드백 없이 작업을 독단적으로 진행하지 않는다.
- 작업 범위가 작더라도 생략하지 않는다.

## 2. 프로젝트 종료 후 팀원 파일 업데이트 (필수)

모든 프로젝트가 공식 완료된 시점에, 해당 프로젝트에 참여한 팀원의 에이전트 markdown 파일(`.claude/agents/<팀명>-<역할명>.md`)을 반드시 업데이트해야 한다.

### 적용 대상
- 프로젝트에 참여한 Jason Company 소속 모든 에이전트

### 업데이트 항목 (필수)

1. **약점 섹션 갱신**
   - 이번 프로젝트에서 해소된 약점: ~~취소선~~ 처리 후 "해소 완료 (YYYY-MM-DD)" 및 근거 명시
   - 이번 프로젝트에서 새로 발견된 약점: 신규 행 추가, "신규 (YYYY-MM-DD)" 태그

2. **성장 목표 섹션 갱신**
   - 달성된 목표: ~~취소선~~ 처리 후 "달성 (YYYY-MM-DD)" 및 근거 명시

3. **프로젝트 경험 기록 섹션 추가/갱신**
   - KPI 자기 업그레이드 프로토콜 섹션 바로 앞에 위치
   - 형식:
     ```
     ### <프로젝트명> (<기간>)
     **역할**: <팀 내 역할>
     **주요 기여**: <핵심 기여 항목 (불릿)>
     **배운 것**: <이번 프로젝트에서 체득한 인사이트>
     **개선 과제**: <다음 프로젝트에서 개선할 구체적 행동>
     ```

4. **조건부 채용 조건 달성 현황 갱신** (해당자만)
   - 달성된 조건: ✅ 표시 + 근거 (산출물 파일명 등)

### 업데이트 시점

- **프로젝트 최종 커밋 완료 직후** 또는 **회고 문서 작성 완료 직후** 중 더 빠른 시점
- agent-supervisor가 있는 경우: agent-supervisor가 업데이트 완료 여부를 확인하고 누락 시 알린다

### 예외 없음

- 프로젝트 규모와 관계없이 (단기 스프린트, 장기 프로젝트 모두) 적용한다.
- 업데이트를 건너뛰는 경우 HR Chief에게 보고하고 사유를 기록한다.
