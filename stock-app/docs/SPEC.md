# US 주식 브리핑 — 기능 명세

> 기준 커밋: `415ba75` (2026-11-11). 동작을 바꾸면 이 문서도 함께 고칩니다.
> 실행 방법과 개발 환경은 [README](../README.md)를 참고하세요.

## 1. 개요

미국 상장 주식을 대상으로 공개 웹 데이터를 모아 한국어로 요약하고, **규칙 기반 점수**로 단기·중기 주가 방향성을 보여 주는 Android 앱과 분석 서버입니다.

- **AI를 쓰지 않습니다.** 크롤링한 데이터, 계산식, 키워드·구문 규칙만으로 판단합니다.
- 무거운 작업(수집·분석·순위 계산·모의 투자)은 모두 **서버가 백그라운드로** 처리합니다. 앱은 요청을 보내고 결과를 조회만 합니다.
- 결과는 참고 자료이며 투자 권유가 아닙니다. 화면마다 이 고지를 표시합니다.

### 범위 밖

- 사용자 계정·로그인·다중 사용자. 서버 하나가 사용자 한 명을 전제로 합니다.
- 실제 주문·증권사 연동
- 미국 외 시장. 비 USD 상장 종목은 거부합니다.
- 실시간 스트리밍 시세. 모든 시세는 조회 시점 기준입니다.

## 2. 구성

```
[Android 앱 (Expo / React Native)] ──HTTP JSON──▶ [분석 서버 (Node.js, :8787)] ──▶ Yahoo Finance, Finviz,
                                                         │                            Google 뉴스 RSS, Google 번역
                                                         └─ server/data/*.json (파일 저장)
```

| 구성 요소 | 위치 | 역할 |
|---|---|---|
| 앱 | `src/` | 화면 4개: 홈, 종목 상세, TOP 10, 모의 투자 |
| API 서버 | `server/src/index.ts` | 라우팅, 10분 주기 스케줄러 |
| 수집 | `server/src/sources/` | 시세·차트·검색·뉴스(Yahoo), 재무·애널리스트·뉴스(Finviz), Google 뉴스 RSS, 제목 번역 |
| 분석 | `server/src/analysis/` | 기술적 지표, 지표 평가, 뉴스 감성·이벤트, 실적, 방향성 점수, 한국어 요약 |
| 리포트 저장소 | `server/src/reports.ts` | 분석 요청 대기열(동시 2개), 결과 저장, 자동 재수집 |
| 추천 | `server/src/recommend.ts` | 유니버스 전체 분석 및 순위 |
| 모의 투자 | `server/src/paper.ts` | 가상 포트폴리오 운용 |
| 공유 타입 | `server/src/types.ts` ↔ `src/lib/types.ts` | 응답 형식. 두 파일은 항상 같게 유지합니다. |

## 3. 기능 명세

### F1. 종목 검색

- 홈 검색창에 티커나 회사명을 입력하면 미국 상장 주식·ETF 후보를 보여 줍니다(`GET /api/search`).
- 인기 종목 칩(AAPL, NVDA, MSFT, TSLA, AMZN, GOOGL, META, SPY, QQQ)을 누르면 바로 분석을 요청합니다.
- 티커 형식(예: `AAPL`, `BRK-B`)에 맞지 않으면 400을 반환하고 안내 문구를 보여 줍니다.

### F2. 백그라운드 분석 요청과 분석 목록

**요청**
- `POST /api/reports/:ticker`는 즉시 202로 응답하고, 서버가 대기열에서 수집합니다(동시 최대 2종목).
- 같은 종목이 이미 대기 중이거나 수집 중이면 새 작업을 만들지 않고 기존 작업을 돌려줍니다.

**상태**
- 상태는 `queued`, `running`, `done`, `error` 중 하나입니다.
- 재수집이 실패해도 **마지막 성공 결과는 유지**합니다.
- 서버를 재시작하면 중단된 작업은 다시 대기열에 들어갑니다.

**목록**
- 홈의 "분석 목록"에 요청한 종목이 표시됩니다.
  - 각 항목: 가격, 등락률, 전망, 수집 시각, 상태
  - 태그: 실적 발표 임박(D-14 ~ 발표 7일 후), 직전 수집 대비 전망 변화(예: "전망 보합 → 상승")
- 정렬은 최근 요청, 등락률, 전망 점수 중에서 고를 수 있습니다. 고른 정렬은 앱에 저장됩니다.
- 당겨서 새로고침, "전체 새로 수집"(`POST /api/reports`), 길게 눌러 삭제를 지원합니다.
- 수집 중인 항목이 있으면 앱이 주기적으로 목록을 다시 불러옵니다.

**자동 재수집**
- 서버가 10분마다 확인해, 마지막 수집이 `AUTO_REFRESH_HOURS`(기본 6시간)보다 오래된 종목을 다시 수집합니다.
- 다시 수집하기 전 결과의 요약(가격, 방향, 점수, 시각)을 `previous` 스냅샷으로 남깁니다.

### F3. 종목 상세 분석

종목이 목록에 없으면 상세 화면을 여는 순간 분석을 요청하고 결과를 기다립니다. 화면은 위에서부터 다음 순서로 구성됩니다.

1. **시세 카드**
   - 회사명, 거래소, 현재가, 등락, 기간별 수익률
   - 실적 정보가 없을 때만 실적 발표일 문구
   - **가격 차트**
     - 기간은 1M, 3M, 6M, 1Y 중 고를 수 있고 기본값은 6M입니다. 데이터보다 긴 기간 탭은 숨깁니다.
     - 차트를 누른 채 움직이면 날짜별 가격과 기간 시작 대비 등락을 보여 줍니다.
2. **지난 수집 대비**: 직전 수집 이후의 가격 변화, 전망 방향 변화, 점수 변화
3. **방향성 판단**
   - 종합 점수(-100 ~ +100), 방향(상승·보합·하락), 신뢰도(높음·보통·낮음)
   - 단기·중기 점수와 한 줄 결론
4. **핵심 요약**: 한국어 문장 여러 줄로, 추세, 실적, 뉴스 이벤트, 애널리스트 의견 등을 다룹니다.
5. **최근 실적**
   - EPS·매출 서프라이즈
   - 전년 동기 대비 성장
   - 발표 후 첫날 반응과 이후 누적 등락
   - 다음 발표 D-day
   - 추정한 발표일이면 그렇다고 표시합니다.
6. **주요 지표 평가**
   - 지표마다 좋음·보통·나쁨 판정과 한 줄 설명을 붙입니다.
   - 좋음은 초록, 나쁨은 주황으로 표시해, 가격 상승·하락 색(빨강·파랑)과 섞이지 않게 합니다.
7. **판단 근거**: 점수에 들어간 각 신호의 값, 방향(강세·약세), 근거
8. **최신 뉴스**
   - 한국어로 번역한 제목과 원문 제목, 출처, 시각, 감성을 보여 줍니다.
   - 주요 이벤트 태그가 붙고, "주요 이벤트" 필터 탭이 있습니다.
9. **출처**: 데이터 출처와 수집에 실패한 출처를 화면 아래에 표시합니다.

헤더의 공유 버튼은 분석 요약을 텍스트로 공유합니다.

### F4. 상승 전망 TOP 10

**대상**
- 미국 대형주 약 60개(`UNIVERSE`)와 분석 목록에 있는 종목
- 모두 F5의 같은 규칙으로 분석합니다.

**순위**
- 점수가 높은 순으로 정렬하고, 점수가 같으면 신뢰도가 높은 쪽이 앞섭니다. 상위 10개를 노출합니다.
- 각 항목: 점수, 방향, 단기·중기 점수, 신뢰도, 목표가 상승여력, 섹터, 한 줄 결론
- 근거는 가장 강한 강세 신호 최대 3개, 위험은 약세 신호 최대 2개를 태그로 보여 줍니다.

**재계산**
- `RECOMMEND_HOURS`(기본 12시간)마다 자동으로 다시 계산하고, "다시 계산" 버튼으로도 실행할 수 있습니다.
- 계산 중에는 진행률을 보여 주고, 끝날 때까지 이전 순위를 유지합니다.
- 계산할 때 6시간 이내의 리포트 분석이 있으면 재사용하고, 나머지 종목은 번역 없이 분석합니다.
- 결과의 절반 이상(또는 10개 미만)이 실패하면 기존 순위를 지우지 않습니다.

**화면 동작**
- 항목을 누르면 종목 상세로 이동합니다.
- 홈의 "▲ 상승 전망 TOP 10" 카드에서 들어갑니다.

### F5. 방향성 점수

**계산 방식**
- 각 신호에 효과(-1 ~ +1)와 가중치를 매깁니다.
- 신호를 기간별로 나눠 가중 평균을 내고, 중기 60% + 단기 40%로 합쳐 -100 ~ +100으로 환산합니다.
- 점수가 ±15를 넘으면 상승·하락, 그 사이면 보합입니다.

| 기간 | 신호 (가중치) |
|---|---|
| 중기 (3~6개월) | 200일선 대비 위치 (2), 50/200일선 교차 (1.5), 6개월 수익률 (1), 애널리스트 평균 의견 (1.5), 목표가 상승여력 (1.5), 내년 EPS 성장 전망 (0.8), 최근 실적 서프라이즈 (발표 45일 이내 1.4, 이후 0.7), 분기 실적 성장 YoY (1), 실적 발표 후 반응 (발표 31~95일 0.7) |
| 단기 (1~4주) | 20일선 대비 위치 (1), MACD 히스토그램 (1.2), RSI 과매수·과매도 (1), 1개월 수익률 (0.8), 최근 7일 뉴스 분위기 (최대 1.2, 기사 수에 비례), 최근 2주 주요 뉴스 이벤트 (최대 1.3), 실적 발표 후 반응 (발표 30일 이내 1.2), 거래량 급증 (0.6) |

**신뢰도**
- 점수의 크기와 신호들이 같은 방향인 정도로 정합니다.
- 단기와 중기의 방향이 엇갈리거나 실적 발표가 7일 안에 있으면 "높음"을 주지 않습니다.

**실적 신호** (`analysis/earnings.ts`)
- **서프라이즈**: Finviz `EPS/Sales Surpr.` 값을 씁니다. 효과는 `0.6·clamp(EPS/10) + 0.4·clamp(매출/4)`입니다.
- **발표 후 반응**: 일봉으로 계산합니다.
  - 기준 봉은 장 전 발표(BMO)면 발표 당일, 장 후 발표(AMC)면 다음 거래일입니다.
  - 첫날 등락과 이후 누적 등락을 구하고, 발표 95일이 지나면 신호에서 뺍니다.
- **직전 발표일 추정**: 다음 발표일이 이미 공지되면 Finviz에 직전 발표일이 나오지 않습니다. 그때는 다음 발표일 70~110일 전 구간에서 거래량이 가장 많은 날을 직전 발표일로 추정합니다.

**뉴스 이벤트** (`analysis/events.ts`)
- 영어 헤드라인에서 다음 이벤트를 구문 규칙으로 찾습니다. 규칙은 순서대로 검사하고 처음 일치한 것을 씁니다.
  - 가이던스 상향·하향, 실적 예상 상회·하회, 투자의견 상향·하향, 목표가 상향·하향
  - 규제 승인·거절, 증자, 소송·조사, 리콜, 경영진 사임, 경고성 전망, 감원
  - 배당 증액, 자사주 매입, 지수 편입, 수주·계약
- 티커, 회사명, 별칭(GOOGL→google 등)이 들어간 헤드라인만 셉니다.
- 최근 14일 이벤트를 반감기 4일로 가중해 합한 뒤 `tanh`로 -1 ~ +1 범위에 맞춥니다.

**뉴스 감성**: 금융 어휘 사전으로 헤드라인을 채점하고, 최근 기사일수록 가중합니다.

### F6. 주요 지표 평가

규칙 기반 임계값으로 각 지표를 좋음·보통·나쁨으로 판정하고 설명 문장을 붙입니다(`analysis/metrics.ts`).

| 그룹 | 지표 |
|---|---|
| 밸류에이션 | P/E, 선행 P/E, PEG, P/S, 애널리스트 목표가, 애널리스트 의견 |
| 성장성 | 매출 성장 YoY, EPS 성장 YoY, 내년 EPS 성장 전망, EPS 서프라이즈 (±3%), 매출 서프라이즈 (±1%) |
| 수익성 | EPS (TTM), 순이익률, ROE |
| 재무 건전성 | 부채비율 (D/E), 배당 |
| 위험·수급 | 베타, 연환산 변동성, 공매도 비율, 거래량 |
| 기술적 흐름 | RSI(14), 20·50·200일 이동평균 대비, MACD, 52주 범위 내 위치 |

### F7. 뉴스 번역

- 수집한 뉴스 제목을 Google 번역 비공식 엔드포인트로 한국어로 옮겨 저장합니다.
  - 여러 제목을 줄바꿈으로 묶어 3,500자 단위로 요청합니다.
  - 번역 결과는 최대 5,000건까지 메모리에 캐시합니다.
- 일부 제목의 번역이 실패하면 그 제목만 원문으로 둡니다. 전부 실패하면 해당 출처를 실패로 표시합니다.
- TOP 10 계산용 분석에서는 번역을 생략합니다.

### F8. 모의 투자

사용자가 금액을 정하면 서버가 F4 순위를 보고 가상으로 매매합니다. 앱에서는 진행 상황을 확인만 합니다.

**시작과 종료**
- `POST /api/paper {amount}`로 시작합니다.
  - 금액은 USD로 $100 ~ $10,000,000이며, 범위를 벗어나면 400입니다.
  - 기존 포트폴리오가 있으면 대체합니다.
- 시작할 때 순위가 오래됐으면 새로 계산한 뒤 매매하고, 그렇지 않으면 바로 매매를 시도합니다.
- `DELETE /api/paper`로 종료합니다. 보유 종목과 기록이 모두 지워집니다.
- 포트폴리오는 서버당 하나입니다.

**매매 규칙** (`DEFAULT_RULES`)

| 항목 | 규칙 |
|---|---|
| 장 판단 | 10분마다 SPY 시세를 조회합니다. 마지막 체결이 30분 이내면 정규장이 열린 것으로 봅니다. **장중에만 매매**하며, 휴장일도 이 방식으로 걸러집니다. |
| 리밸런싱 시점 | 아직 반영하지 않은 새 순위가 나오면 한 번 합니다. 24시간이 넘은 순위는 쓰지 않습니다. 순위 계산이 끝나면 바로 실행을 시도합니다. |
| 매도 | 점수 < 0 또는 순위 25위 밖이면 팝니다. 순위 계산에 실패해 빠진 보유 종목은 유지합니다. |
| 손절 | 시세를 갱신할 때 매입 원가 대비 -10% 이하이면 즉시 팝니다. |
| 매수 | 10위 안, 점수 +20 이상, 미보유, 쿨다운이 지난 종목을 순위 순으로 골라 빈 자리를 채웁니다. 최대 5종목입니다. |
| 비중 | 종목당 총 평가액의 1/5을 사되, 남은 현금이 부족하면 남은 후보끼리 나눕니다. 슬롯 금액의 10% 미만이면 사지 않습니다. 소수점 주식을 허용합니다. |
| 쿨다운 | 판 종목은 3일간 다시 사지 않습니다. |
| 수수료 | 매수·매도마다 체결 금액의 0.25%입니다. 매입 원가에 포함되고 실현 손익에서 빠집니다. |
| 체결가 | 매매 직전에 조회한 최신 시세입니다. 슬리피지는 없습니다. |
| 벤치마크 | 시작할 때의 SPY 가격 대비 현재 SPY 가격으로, 같은 금액을 SPY에 넣었을 때의 수익률을 계산합니다. |

**기록**
- 매매 기록은 최신순으로 최대 300건입니다. 시각, 매수/매도, 종목, 수량, 가격, 금액, 수수료, 실현 손익, 사유가 남습니다.
  - 사유 예: "TOP 2위 · 점수 +63 · 200일 이동평균 대비 +21.6%", "손절 기준(-10%) 도달: -10.4%"
- 평가금액 추이는 시간당 1개 지점, 최대 3,000개입니다. 각 지점에 SPY 벤치마크 값을 함께 기록합니다.
- 시세 갱신, 손절, 리밸런싱은 직렬로 실행해 서로 겹치지 않습니다.

**화면**
- **시작 전**: 금액 입력($1,000, $10,000, $100,000 프리셋)과 규칙 설명을 보여 줍니다.
- **운용 중**
  - 요약: 총 평가금액, 손익(금액·%), 장 상태(장 중·장 마감·첫 매수 대기), 투자 원금, 현금, 실현 손익, 낸 수수료, 같은 기간 SPY 수익률, SPY 대비 차이(%p)
  - 평가금액 추이 차트. 누르면 시점별 값을 보여 줍니다.
  - 보유 종목: 수량, 평단 → 현재가, 평가액, 손익, 비중, 현재 순위·점수. 누르면 종목 상세로 이동합니다.
  - 매매 기록: 최근 10건을 보여 주고 "전체 보기"로 모두 펼칩니다.
  - 규칙 설명과 "모의 투자 끝내기"(확인 후 삭제)
- 화면이 열려 있는 동안 60초마다 다시 불러옵니다.
- 홈의 "모의 투자" 카드에 평가금액과 수익률을 표시합니다.

## 4. API

모든 응답은 JSON이며 CORS를 허용합니다. 오류 응답 형식은 `{ "error": "한국어 메시지" }`입니다.

| 메서드 | 경로 | 설명 | 응답 |
|---|---|---|---|
| GET | `/health` | 상태 확인 | `{ok:true}` |
| GET | `/api/search?q=` | 미국 주식·ETF 검색 | `{results: SearchResult[]}` |
| GET | `/api/reports` | 분석 목록 | `{reports: ReportSummary[], autoRefreshHours}` |
| POST | `/api/reports` | 목록 전체 재수집 | 202 `{queued, reports}` |
| POST | `/api/reports/:ticker` | 분석(재수집) 요청 | 202 `ReportSummary` |
| GET | `/api/reports/:ticker` | 전체 분석 결과 | `Report`, 요청한 적 없으면 404 |
| DELETE | `/api/reports/:ticker` | 목록에서 삭제 | 204 / 404 |
| GET | `/api/recommendations` | TOP 10과 계산 상태 | `Recommendations` |
| POST | `/api/recommendations` | 순위 재계산 시작 | 202 `Recommendations` |
| GET | `/api/paper` | 모의 투자 현황 | `Portfolio` (`status: "none"` 또는 `"active"`) |
| POST | `/api/paper` | 모의 투자 시작, body `{amount}` | 201 `Portfolio`, 금액 오류면 400 |
| DELETE | `/api/paper` | 모의 투자 종료 | 204 |

업스트림 수집 오류는 502로 응답합니다. 정의되지 않은 메서드는 405, 정의되지 않은 경로는 404입니다.

## 6. 저장과 스케줄

| 파일 (`server/data/`, git 제외) | 내용 | 환경 변수 |
|---|---|---|
| `reports.json` | 분석 목록과 결과 | `DATA_FILE` |
| `recommendations.json` | 마지막 순위 계산의 전체 결과 | `RECOMMEND_FILE` |
| `portfolio.json` | 모의 투자 상태 | `PAPER_FILE` |

- 파일은 임시 파일에 쓴 뒤 이름을 바꾸는 방식으로 저장합니다.
- 서버 시작 시 불러오며, 예전 형식이면 새 필드를 채워 넣습니다.

**10분 주기 작업** (서버 시작 시 1회 실행 후 반복)
1. 오래된 리포트를 자동으로 재수집합니다(`AUTO_REFRESH_HOURS`, 기본 6, 0이면 끔).
2. 순위가 오래됐으면 재계산하고, 끝나면 모의 투자 리밸런싱을 시도합니다(`RECOMMEND_HOURS`, 기본 12, 0이면 요청할 때만).
3. 모의 투자의 시세를 갱신하고 손절·리밸런싱을 확인합니다.

기타 환경 변수: 서버 `PORT`(기본 8787), 앱 `EXPO_PUBLIC_API_URL`.

## 7. 화면 규칙

- 가격 등락은 한국식 색을 씁니다. 상승은 빨강, 하락은 파랑입니다.
- 지표 평가는 좋음 초록, 나쁨 주황으로, 등락 색과 구분합니다.
- 라이트·다크 테마를 지원합니다.
- 모든 문구는 한국어로 씁니다. 시각은 "n분 전"처럼 상대 시간으로 표시합니다.
- 오류는 화면 안의 문구나 알림 창으로 보여 줍니다. 서버에 연결하지 못하면 접속 주소를 확인하라고 안내합니다.

## 8. 테스트

`cd server && npm test`로 실행합니다(node:test, 35개). 다루는 내용은 다음과 같습니다.

- 기술적 지표, 감성, 방향성 임계값
- 지표 평가, Finviz 파싱, 실적 날짜 해석
- 실적 반응과 직전 발표일 추정, 뉴스 이벤트 탐지와 회사명 필터
- 리포트 대기열과 저장, 번역 묶음 처리
- 추천 순위
- 모의 투자: 금액 검증, 장중에만 매매, 균등 매수와 수수료, 점수·순위·손절 매도, 쿨다운, 재시작 후 복원

앱은 `npm run typecheck`, `npm run lint`, `npx expo export --platform android`로 검증합니다.

## 9. 알려진 한계

- 비공식 웹 경로를 크롤링하므로, 사이트 구조가 바뀌면 일부 항목이 비거나 해당 출처가 실패합니다.
- 뉴스 감성과 이벤트는 영어 헤드라인 규칙이라 반어법, 간접 표현, 맥락을 놓칠 수 있습니다.
- 직전 실적 발표일 추정은 거래량에 기댄 휴리스틱이라 하루 정도 어긋날 수 있습니다.
- 점수는 추세 추종 성향이 있어 이미 많이 오른 종목을 높게 평가하기 쉽습니다. 모의 투자도 같은 성향을 가집니다.
- 모의 투자는 사용자 한 명, 포트폴리오 하나, USD만 지원합니다. 슬리피지와 세금은 반영하지 않습니다.
- 인증이 없으므로 서버 주소를 아는 사람은 누구나 API를 호출할 수 있습니다. 개인 테스트 용도로만 쓰세요.
