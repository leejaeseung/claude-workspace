# TicketRush 8주 팀 회고

**날짜**: 2026-07-05 (W8)  
**참석**: 박지훈, 하진우, 강민서  
**형식**: 팀원별 자기 회고 + 공통 KPT

## 1. 팀원별 회고

### 박지훈 (팀 리더)

**잘 한 것**

- G1~G4 갈등 시나리오를 사전 설계하고 실제로 운영했다. "갈등은 숨기지 않고 테이블에 올린다"는 원칙이 팀 문화로 자리잡았다.
- Arrow-kt 파일럿을 내가 먼저 시작하고 공유 세션을 열었다. 새 기술을 리더가 직접 시험하고 팀에 전파하는 방식이 효과적이었다.
- G2에서 하진우에게 결정권을 위임했다. ADR-009까지 하진우가 혼자 썼다.

**아쉬운 것**

- 좌석 선택 화면 SSE 모듈을 완성했지만 FE E2E 테스트를 1건만 작성했다. 처음부터 "E2E 3건"보다 "1건 완벽 작성"을 목표로 잡았더라면 품질이 더 좋았을 것이다.
- Context 표준화 효과를 W4/W8 두 번 측정하기로 했는데 W4 측정을 건너뛰었다. 약속한 측정은 반드시 한다.

**다음 프로젝트에서 가져갈 것**

갈등 조율 프로세스 v1. 다음 프로젝트에서도 G1~G4 같은 의도적 갈등 시나리오를 사전 설계한다.

---

### 하진우 (시니어 개발자)

**잘 한 것**

- Kafka `order.created` 설계를 파티션 키(ADR-002)부터 파티션 수(ADR-009)까지 끝까지 소유했다. 중간에 박지훈이 "네가 결정해"라고 했을 때 도망치지 않고 데이터로 판단했다.
- 장애 대응 런북을 처음 써봤는데, 작성하면서 "이 장애는 어떻게 알아챌까"를 계속 물었다. 알림 설계(ADR-008)와 런북이 자연스럽게 연결됐다.
- 강민서의 userId 파티션 키 주장을 끝까지 들었다. 처음엔 "틀렸다"는 생각이 앞섰는데, 박지훈이 던진 두 질문(비즈니스 요건, Saga 상관)을 통해 함께 결론에 도달하는 방식이 훨씬 좋았다.

**아쉬운 것**

- Testcontainers 기반 Kafka 통합 테스트를 계획했지만 단위 테스트로만 마무리했다. 다음 프로젝트에서는 인프라 테스트를 W2 내에 셋업한다.
- 시스템 설계서 v1을 W3에 너무 빨리 썼다. 아직 결정되지 않은 부분을 "예상"으로 채웠고, v2에서 절반 이상 바뀌었다. 설계서는 결정이 확정된 시점에 쓴다.

**다음 프로젝트에서 가져갈 것**

"의견이 아닌 데이터에 묶는다." 기술 토론에서 주장보다 측정 조건을 먼저 합의하는 방식.

---

### 강민서 (미드레벨 개발자)

**잘 한 것**

- FE 미경험으로 시작해 대기열 화면과 결제 결과 화면을 완성했다. 박지훈이 1주 차에 페어 프로그래밍 두 번을 잡아줬는데, 그 90분이 이후 2주 분량의 삽질을 막아줬다.
- G3 갈등에서 FE 입장으로 직접 발표했다. 말하기 싫었는데 발표 후 오히려 하진우가 "미처 몰랐다"고 했다. 목소리를 내는 것이 이 팀에선 안전하다는 걸 배웠다.
- W8에서 좌석 즐겨찾기를 혼자 설계하고 구현했다. G4 회의에서 박지훈이 W8 1순위라고 약속했던 것을 내가 직접 완성했다. 처음으로 기능 하나의 처음부터 끝을 다 내 손으로 만들었다.

**아쉬운 것**

- userId 파티션 키를 주장했을 때 하진우의 반론을 처음엔 "내 의견이 무시당한다"고 느꼈다. 그게 감정이었다. 박지훈의 질문("비즈니스 요건에 있나?")을 듣고 나서야 기술적으로 생각할 수 있었다. 앞으로는 반론이 오면 먼저 기술적 근거를 물어본다.
- Kotest 단위 테스트는 썼는데 통합 테스트는 하나도 못 했다. 테스트는 기능 개발과 동시에 한다.

**다음 프로젝트에서 가져갈 것**

"비즈니스 요건 먼저 확인." 기술 선택 전에 요건 문서를 먼저 읽는다.

## 2. 팀 공통 KPT

### Keep (계속할 것)

- **갈등 조율 프로세스 v1** — 사실 분리 → 데이터 → ADR → 회고 → 패턴화
- **ADR 문화** — 모든 기술 결정은 ADR로. 결정이 틀렸을 때도 "왜 그렇게 결정했는지"가 남는다
- **위임 의도 명시** — "이 결정은 네가 해"라고 명확하게 말하는 것
- **Context 작업 맥락 템플릿** — 목표/제약/참고파일/완료기준 4항목 강제

### Problem (문제점)

- **FE E2E 테스트 부족** — Playwright 1건만 완성. 2건은 기술 부채로 남음
- **통합 테스트 부재** — Testcontainers + Kafka 통합 테스트를 계획만 하고 구현 못 함
- **시스템 설계서 타이밍** — 결정 전에 설계서를 쓰면 나중에 절반을 다시 씀
- **측정 약속 미이행** — W4 Context 토큰 측정 건너뜀

### Try (다음에 시도할 것)

- **인프라 테스트 W2 완료** — Testcontainers 셋업을 기능 개발보다 먼저
- **설계서 = 결정 후 작성** — "예상" 섹션은 ADR 확정 후 이동
- **측정 일정 캘린더 등록** — 측정 약속은 PR처럼 추적
- **Playwright E2E 2건 완성** — 다음 프로젝트 W4 내 완료 목표
