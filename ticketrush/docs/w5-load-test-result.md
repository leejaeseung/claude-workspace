## 2. 시나리오 A — seat-rush.js (좌석 잠금 3,000 RPS)

### 목표 지표 vs 실측

| 지표 | 목표 | 실측 | 달성 |
|------|------|------|------|
| seat-api HTTP P99 | < 800ms | **312ms** | ✅ |
| ZGC STW pause P99 | < 10ms | **3.2ms** | ✅ |
| 중복 점유 발생 | 0건 | **0건** | ✅ |
| 에러율 | < 0.5% | **0.08%** | ✅ |
| seat_lock_success_rate | ≥ 30% | **34.7%** | ✅ |

### 부하 프로파일 결과

```
[ramp-up  0~30s ] P99:  95ms @ 1,000 RPS
[climb   30~90s ] P99: 248ms @ 1,000~3,000 RPS
[sustain 90~120s] P99: 312ms @ 3,000 RPS  ← 최대 부하
[ramp-dn 120~130s] 정상 수렴
```

### 주요 관찰

- **ZGC 효과 확인**: G1GC 기준 P99 1,240ms → ZGC 전환 후 312ms (-75%). ADR-004 예측과 일치.
- **핫 좌석 패턴**: 상위 10개 좌석(70% 트래픽) 에서 Redis Lua 원자성 작동 — 중복 점유 0건 유지.
- **메모리**: JVM Heap 최대 사용률 71% (`-Xmx1g` 기준). ADR-004 85% 제한 이하.

## 3. 시나리오 B — G1 비교 (g1-lock-comparison.js)

> ADR-005 판정 기준 최종 확인

| 지표 | Redis Lua | SELECT FOR UPDATE | 비율 |
|------|-----------|------------------|------|
| P99 응답시간 | **8.3ms** | **148ms** | **0.056** |
| 커넥션 포화 | 없음 | 10/10 (피크) | — |
| 오류율 | 0.08% | 2.1% | — |

**판정**: `Redis P99 (8.3ms) ≤ DB P99 (148ms) × 0.5 (74ms)` → **True** ✅  
**결론**: ADR-001 Redis Lua 채택 최종 확정. ADR-005 갱신 완료.
